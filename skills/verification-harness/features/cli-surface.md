# CLI Surface (`bin/loopx-flow`)

`bin/loopx-flow` is the primary user-facing and agent-facing CLI surface of `loopx-workflow`. It initializes workflow scaffolding, scaffolds Feature Capsules, enforces fail-closed Gate 1 specification locks (`approve contract` / `gate verify contract`), and delegates managed task execution (`todo claim` / `todo done`) to the LoopX control plane while isolating runtime artifacts from the host and repository root. Across the five verification dimensions (`Surface`, `Run`, `Drive`, `Observe`, `Isolate`), discrepancies uncovered during a pass are triaged strictly into `Doc Drift`, `Harness Gap`, or `Product Bug`.

## Sub-features

- `cli-help-surface` prints the orchestrator usage banner and core command table (`feature`, `approve`, `check`, `pr`, `review`, `merge`, `gate`, `doctor`, `todo`) with exit code `0`.
- `cli-init-and-subdir-anchor` rejects non-TTY first-time `init` without `loopx-workflow.config.json` (`REQ-AUTH-MODE-1`), completes `init` once explicit `loopx-workflow.config.json` is present to create `.loopx/tmp` and `.git/hooks/pre-commit`, and anchors `REPO_ROOT` identically when `bin/loopx-flow` is invoked from a nested subdirectory (`subdir/nested`).
- `cli-feature-and-gate1-negative` verifies the installed `pre-commit` hook blocks direct `main` commits, scaffolds the 6-file Feature Capsule (`00-INDEX.md` ~ `05-evidence.md`) on branch `feature/<name>`, and fails closed (`exit !== 0`) on `gate verify` and `approve contract` when human approval prerequisites (`01-decisions.md` `APPROVED` + Gate 1 authorization) are missing, leaving zero `FROZEN & APPROVED` markers.
- `cli-gate1-approve-and-tamper-detect` completes Gate 1 `approve contract` (`independent` mode with a second-principal `gate=1` PR comment), locks the exact `04-contract.md` SHA-256 in LoopX `contract_revision`, passes `gate verify contract`, and immediately blocks (`exit !== 0`) when a single byte of `04-contract.md` is tampered with afterward.
- `cli-todo-managed-canary` drives real `loopx 2.3.x` (`bootstrap` -> `register-agent` -> `todo add` -> `loopx-flow todo claim` -> `loopx-flow todo done`) against a disposable `--registry` and `--runtime-root`, proving 5-tuple claim cache creation and atomic release/cleanup without touching the main repo or host `~/.loopx`.

## How to get to it (user POV)

- Run `bin/loopx-flow --help` from the repository root or any tracked subdirectory inside a target Git worktree.
- Run `bin/loopx-flow init`, `bin/loopx-flow feature <name>`, `bin/loopx-flow approve contract <name>`, and `bin/loopx-flow gate verify <decisions|contract> <name>` during Stages 0~4.
- Run `bin/loopx-flow todo claim <todo-id> --goal-id <goal-id>` and `bin/loopx-flow todo done <todo-id> --goal-id <goal-id>` during Stage 5 managed task execution.
- Run `LC_ALL=en_US.UTF-8 node skills/verification-harness/scripts/prove-cli-surface.js --output-dir <proof-dir>` to execute the complete cold-start live Prove pass.

## Driving it with prove-cli-surface

Preconditions:

- **Surface & Run**: `bin/loopx-flow`, `lib/paths.sh`, and `lib/paths.js` exist. (`./scripts/preflight-check.sh` is a Stage 0 environment precondition run by CI / the operator; `prove-cli-surface` does not drive it.) The harness source worktree must be clean and committed — Prove fails closed on a dirty workspace and records `source_head`, `diff_fingerprint`, and `contract_revision`.
- **Isolate**: `prove-cli-surface.js` allocates a disposable run directory via `lib/paths.js#createRunDir('prove-cli-surface')` under `LOOPX_TMP_DIR` and sets isolated `HOME`, `LOOPX_TMP_DIR`, and `LOOPX_REGISTRY` for every spawned `bin/loopx-flow` child process.
- **Drive & Observe**: Output directory `--output-dir <proof-dir>` points outside the disposable sandbox so Proof JSON and Markdown survive teardown.

- **Check help surface (`cli-help-surface`).** Invoke `bin/loopx-flow --help` inside the isolated Git workspace. Exit code is `0`, and `stdout` contains `LoopX AI-Native Flow Orchestrator`, `approve contract`, `gate verify`, `todo claim`, and `todo done`.
- **Verify `init` non-TTY guard, `init` scaffolding, and subdirectory root anchoring (`cli-init-and-subdir-anchor`).** First run `bin/loopx-flow init` without `loopx-workflow.config.json` on non-TTY stdin and confirm it exits non-zero (`REQ-AUTH-MODE-1` refuses silent default). Next write `loopx-workflow.config.json` (`authorization_mode: "independent"`), run `bin/loopx-flow init` with Contract Fake `loopx`/`gh`, create `subdir/nested`, and run `bin/loopx-flow status --next demo-slice` from `subdir/nested`. `init` and `status --next` exit `0`, `.loopx/tmp` and `.git/hooks/pre-commit` exist at the repo root (never under `subdir/nested/.loopx`), and `stdout` reports `Feature: demo-slice` with `Read-only projection`.
- **Verify `pre-commit` main guard, scaffold capsule, and assert fail-closed Gate 1 negatives (`cli-feature-and-gate1-negative`).** Attempt a direct `git commit` on `main` and confirm the installed `pre-commit` hook blocks it (`status !== 0`), then reset clean. Run `bin/loopx-flow feature demo-slice` with Contract Fake `loopx`, followed by `bin/loopx-flow gate verify contract demo-slice` and `bin/loopx-flow approve contract demo-slice` while the capsule is still unapproved `DRAFT`. `feature` exits `0` on branch `feature/demo-slice` and writes all 6 capsule files (`00-INDEX.md` ~ `05-evidence.md`); both premature Gate 1 commands exit non-zero (`status !== 0`) and `04-contract.md` remains `DRAFT` (never `FROZEN & APPROVED`).
- **Approve Gate 1 contract and prove tamper rejection (`cli-gate1-approve-and-tamper-detect`).** Author valid Stage 1~4 capsule specs referencing `ADR-0011`, commit clean Git state on `feature/demo-slice`, seed a second-account `gate=1` PR comment matching the exact post-lock SHA-256 via Contract Fake `gh`, and run `bin/loopx-flow approve contract demo-slice`. Exit code is `0`, `04-contract.md` is marked `FROZEN & APPROVED`, `gate verify contract demo-slice` exits `0`, and appending one trailing comment line to `04-contract.md` causes the next `gate verify contract demo-slice` to fail closed (`status !== 0`) with `CONTRACT_TAMPERED` diagnostics.
- **Drive real LoopX managed todo claim/done (`cli-todo-managed-canary`).** When `loopx 2.3.x` is installed on `PATH`, bootstrap an isolated project + `--runtime-root` + `--registry`, register `agent-prove`, add an agent todo, and run `bin/loopx-flow todo claim <tid> --goal-id vh-canary-goal` followed by `bin/loopx-flow todo done <tid> --goal-id vh-canary-goal --evidence "cli-surface cold-start prove"`. Both commands exit `0`, the 5-tuple claim cache file `$LOOPX_TMP_DIR/claims/vh-canary-goal--<tid>.json` is created on `claim` and atomically deleted on `done`; `loopx todo list --goal-id vh-canary-goal --role agent` resolves the added agent todo's `todo_id` before claim, and `loopx-flow todo done` then completes it with `status === "done"`. If `loopx 2.3.x` is absent (or installed at an unsupported version) on a minimal runner, record `verified_unreachable` with the missing/unsupported `loopx` prerequisite; `overall_status` then degrades to `partial` and the step is listed under `triage.harness_gap` — a Prove without `loopx 2.3.x` must never claim `overall_status: passed`.
- **Tear down sandbox and verify Proof survival.** Remove the disposable sandbox directory and assert `!fs.existsSync(sandboxDir)`, `fs.existsSync('<proof-dir>/cli-surface-proof.json')`, `fs.existsSync('<proof-dir>/cli-surface-proof.md')`, unchanged `git status --porcelain` and `.loopx/**` file manifest for the caller repo, and unchanged digests for `<REPO_ROOT>/.loopx/registry.json` and `~/.loopx/registry.global.json`.

## Gotchas

- First-time `loopx-flow init` without an existing `loopx-workflow.config.json` intentionally fails closed when stdin is not a TTY (`REQ-AUTH-MODE-1`: never silently default `authorization_mode`). Headless automation must assert that negative guard first, then write an explicit `loopx-workflow.config.json` before exercising `init`.
- `loopx-flow init` installs `.git/hooks/pre-commit`, which physically blocks direct commits on `main` or `master`. Subsequent test commits inside the sandbox must happen on `feature/<name>` after `loopx-flow feature <name>` switches branches.
- `single_owner` Gate 1 `approve contract` intentionally requires an interactive `/dev/tty` confirmation (`ADR-0009` T1/T2); headless automation must not spoof `/dev/tty` or pass `--yes` (which is explicitly rejected). Drive positive headless Gate 1 lock verification through `independent` mode with a second-principal `gate=1` comment matching the locked `04-contract.md` SHA-256.
- `approve contract` computes `spec_commit` only when tracked Git files are clean (`git status --porcelain --untracked-files=no` is empty); uncommitted edits to `01-decisions.md` or `04-contract.md` will fail closed before SHA locking.
- On macOS, `LC_ALL=C.UTF-8` can emit `bash: warning: setlocale: LC_ALL: cannot change locale (C.UTF-8)` on child shells; prefer `LC_ALL=en_US.UTF-8` (or inspect structured JSON / exit codes) so stderr assertions do not confuse OS locale warnings with CLI errors.
- During maintenance triage, never mask a real CLI regression in `Gotchas`: wrong map text is `Doc Drift`, missing script/stub support is `Harness Gap`, and broken CLI fail-closed behavior is a `Product Bug` that must block and be fixed in code with a failing unit test first.
